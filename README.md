# 撤销栈与操作合并（从 0 实现）

起始环境只有这份说明、`samples/**` 与 `.gitignore`，没有代码可抄。交付：`undostack` 包（Python 3.13、标准库）、命令行
`python -m undostack`、用样例生成的 `history.html`、`tests/`（`unittest`）。

## 1. 范围

要做的：读编辑操作序列，按第 2 节把连续操作合并成栈条目，支持撤销与重做，逐行写出每步之后的栈视图与文本状态
（`replay`）；把 `samples/scripts/` 全部序列摊成自包含页面（`history`）。

不做的：真实编辑器渲染（不画光标、不高亮、不导出图片）、删除与替换、选区与多光标、输入法组合、多文档与协同、落盘与
跨进程共享、非法脚本容错、联网、第三方库、CDN、构建与安装步骤。

## 2. 口径与公式

**时间**：`t` 是非负整数毫秒、按文件先后非降序；不读系统时钟、不 `sleep`、不取随机数。

**编辑操作**：`input` 在 `pos` 插入 1 个字符、`paste` 插入 2..8 个，都要求 `pos` 正好是当前光标，插入后光标落在插入
内容末尾；`caret` 只挪光标；内容只含小写字母与数字。条数与回退量按操作算：`paste` 再长也只算 1 条，`caret`、`undo`、
`redo` 不算操作、不进栈。

**合并判定**：四条全满足才并进栈顶条目：① 类型相同（`input` 配 `input`、`paste` 配 `paste`）；② 与栈顶条目最后一条
操作的 `t` 差 ≤ **500**；③ 位置连续（`pos` 等于栈顶条目结束时的光标）；④ 栈顶条目覆盖还不足 **6** 条。任一条不满足就
另起条目；光标位置变过、`undo`、`redo`（含 noop）之后也一定另起条目。

**栈长上界**：条目数 ≤ **8**；新条目入栈后超过 8 就把栈底那条挤出，它不再可撤销。

**单次撤销回退量的下界**：`undo` 从栈顶往下弹，累计覆盖 ≥ **3** 条才停，栈里不够 3 条就弹空；于是每次撤销退 3..8 条
（栈内不足时退空），每条最多覆盖 6 条，不会退一大片。

**重做分支**：一次撤销弹掉的条目合成一个重做组（组内保持原先后），`redo` 把最近一组整体放回栈顶；出现新编辑时重做组
全部丢弃（截断），`caret` 不丢弃；空栈 `undo`、空重做组 `redo` 都是 noop（栈、文本、光标、重做组都不动，但仍打断合并）。

## 3. 状态机与数据结构

状态是 `(文本, 光标)`，只被编辑操作、`caret`、`undo`、`redo` 改变。条目字段：编号（从 1 起、只增不减）、类型、覆盖的
操作序号（升序不重叠）、`t` 起止，以及两份**状态快照**：`before` 是第一条操作前的状态、`after` 是最后一条操作后的
状态；撤销恢复 `before`、重做恢复 `after`，弹出与放回都不重算快照。

五种迁移：编辑 → 并入栈顶或另起条目（另起后查上界、挤栈底）、`caret` → 改光标、`undo` → 弹一组、`redo` → 放回一组、
新编辑 → 先丢弃重做组；栈从底到顶是时间先后，重做组按组压成栈。

## 4. 输入输出与文件格式

文件都是 UTF-8、无 BOM、LF 行尾、末行有换行；脚本与轨迹是纯 ASCII。

### 4.1 操作序列 `samples/scripts/<名>.txt`

一行一条记录，字段用单个空格分隔、写成 `k=v`：

```
input pos=<整数> text=<1 个字符> t=<毫秒>
paste pos=<整数> text=<2..8 个字符> t=<毫秒>
caret pos=<整数> t=<毫秒>
undo t=<毫秒>
redo t=<毫秒>
```

`#` 开头是注释、空行忽略；样例保证 `t` 非降序、编辑操作的 `pos` 落在当时的光标上。

### 4.2 轨迹 `samples/expected/<名>.txt`

脚本里每条记录一行，字段用 `|` 分隔：

```
<步号>|<记录>|S=<栈长>/8|T=<文本或->|C=<光标>|R=<重做组或->|<条目;条目;…>
```

- `<步号>` 从 1 起、不补零；`<记录>` 是那一行原样；`T=` 是当前文本、空写 `-`；`C=` 是光标偏移。
- `R=` 是重做组，空写 `-`；组间用 `+`（先撤销的组在前）、组内按原先后写 `#编号`、用 `,` 分隔，如 `#3,#4+#1`。
- 条目按栈底到栈顶用 `;` 分隔、栈空写 `-`；每条写 `#<编号> <类型> n=<覆盖条数> ops=<操作序号>`，序号用 `a-b` 表示
  区间、单条写 `a`、多段用 `+` 连（如 `1-6+10-11`）。

`T=` 与 `C=` 是快照落地的样子：撤销后等于被弹组最底条目的 `before`，重做后等于被放回组最顶条目的 `after`。

### 4.3 命令行

在仓库根目录执行，日志走 stderr；退出码 0 跑完、1 输入不可用且不写输出、2 用法错误：

```
python -m undostack replay  <操作序列> <轨迹文件>
python -m undostack history <页面文件>
```

`history` 按文件名字典序读 `samples/scripts/` 全部序列。

### 4.4 页面

`history` 写一个自包含 HTML：数据内联、不 `fetch`、不引 CDN、不起服务，双击即开，跑两遍逐字节相同。每个序列一节
（`<section data-script="<名>">`）：① 节首写序列名、记录数、操作条数、`栈长 n/8`（元素带 `data-stack="n/8"`）、撤销与
重做次数；② 左边一条记录一行（`<div class="op" data-op="<操作序号或->">`），编辑操作写序号、类型、位置、内容、时刻；
③ 右边合并后的栈条目一条一行（`<div class="entry" data-entry="<编号>" data-ops="<覆盖序号>" data-count="<条数>">`），
写编号、类型、覆盖条数；④ 色块把两边对上：一条目一色，左边被它覆盖的行着色；⑤ 数字、分组与 `data-ops` 只来自引擎。

## 5. 性能与验收口径

规模：单脚本记录与编辑操作都 ≤ 5×10^4；测试机（Windows + Python 3.13、单进程单线程）：`replay` ≤ 2 秒、`history`
≤ 5 秒，`replay` 额外峰值内存 ≤ 64 MiB（`tracemalloc` 扣基线）。

1. 环境：Python 3.13、只用标准库、无构建无网络；运行期只写 `var/`（不入库）与命令行指定的输出。
2. 正确性：每个样例的 `replay` 结果与 `samples/expected/<名>.txt` 逐字节相同（含末行换行）。
3. 两条界：每一步后栈长 ≤ 8；每次 `undo` 回退 3..8 条（不足 3 条时退空），六个样例逐步可对。
4. 分支：`04-branch` 里新编辑之后的 `redo` 是 noop、`caret` 不截断；`06-edges` 里空栈撤销与空重做组都是 noop。
5. 确定性：同一脚本跑两遍 sha256 相同、`history` 逐字节相同；不写时间戳与绝对路径，不依赖系统时钟、随机数、哈希随机化
   与遍历顺序。
6. 页面与测试：4.4 五项齐全、数字与 `replay` 一致、双击能开；`python -m unittest discover` 能跑通，测试只读
   `samples/`。

## 6. 样例说明

`scripts/<名>.txt` 与 `expected/<名>.txt` 一一对应；括号里是 记录数/操作条数/最终栈长/撤销次数/重做次数：

| 样例 | 场景与关键结果 |
| --- | --- |
| `01-typing-20` | 连着敲 20 下按 6/6/6/2 合成 4 条；撤销三次（退 8/6/6）回到原处、重做三次复原（26/20/4/3/3） |
| `02-gap-bursts` | 同位置隔 500 毫秒合并、隔 501 毫秒另起；两次撤销各退 4 条（12/8/4/2/2） |
| `03-alt-positions` | 位置交替每条各起一条；第 9、10 条入栈挤掉栈底 #1、#2；一次撤销退 3 条（23/11/8/1/1） |
| `04-branch` | 撤销后又敲新内容：分支被截断、之后的 `redo` 是 noop；中途 `caret` 不截断（16/8/2/3/3） |
| `05-paste` | 三次粘贴合成一条（n=3）；`input` 与 `paste` 不同类不合；差 501 毫秒另起（11/9/4/1/1） |
| `06-edges` | 一条满 6 条操作即另起；空栈撤销与空重做组是 noop（20/10/2/5/5） |

`samples/notes.md` 是现场记录，不参与判定；核对就是 `replay` 跑一遍后逐字节比。
